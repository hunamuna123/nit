# Нить — пошаговые инструкции, которые проходят до конца

Платформа интерактивных инструкций с чек-листами для повторяющихся задач: от сборки ПК
до справки в деканате. Ученик проходит инструкцию в режиме «отметил шаг — перешёл дальше».
Платформа собирает сигналы о том, где ученики спотыкаются, а автор видит узкие места,
получает от ИИ разбор комментариев и выпускает исправленную версию, которую можно сравнить с прошлой.

**Сайт: https://nit.envision.press** · API: https://nit.envision.press/api/docs

> Трек «Веб-разработка». Фронтенд — Nuxt 4, бэкенд — FastAPI, PostgreSQL с pgvector, ИИ — GigaChat.

## Что сделано

**Задача-минимум**
- **Каталог.** Категории, фильтры (сложность, время, проверено экспертом) и пять сортировок, в том числе по индексу полезности.
- **Страница прохождения.**
  - Один экран — один шаг, прогресс-бар.
  - Чек-лист шага: пока все пункты не отмечены, перейти дальше нельзя.
  - Горячие клавиши: `1`–`9` отмечают пункты, `Enter` — дальше, `←` — назад, `?` — «Застрял».
  - Прогресс сохраняется, в том числе для гостя без регистрации; после входа гостевой прогресс переносится в аккаунт.
- **Кабинет автора.**
  - WYSIWYG-редактор шагов на TipTap, текст хранится в Markdown.
  - Шаги перетаскиваются мышью, есть чек-листы и картинки (загружаются в S3).
  - Автосохранение черновика; публикация создаёт новую версию.

**Задача-максимум**
- **Комментарии к шагам и «полезно / не полезно».** У комментария есть тип: вопрос, совет или комментарий. Метки «эксперт» и «автор» выводятся рядом с именем.
- **Форк инструкции.** Ключи шагов у форка совпадают с оригиналом, поэтому шаги можно сопоставлять между собой. На странице оригинала есть блок «улучшенные версии».
- **Предложения правок как pull request.** Автор видит «было / стало» (визуально или построчно) и вливает правку в черновик одной кнопкой.
- **Роли ученика, эксперта и администратора.**
  - Пользователь подаёт заявку на роль эксперта, администратор её одобряет.
  - Эксперт проверяет инструкции своих категорий из очереди и ставит вердикт.
  - Проверенная инструкция получает бейдж и бонус к рейтингу.
- **Умный поиск** — гибрид трёх способов. Результаты сливаются через Reciprocal Rank Fusion, совпадения подсвечиваются.

  | Способ | Как работает | Пример |
  |---|---|---|
  | Полнотекстовый | PostgreSQL FTS с русской морфологией | «справки» находит «справку» |
  | С опечатками | триграммы `pg_trgm` | «Dockr» находит Docker |
  | Семантический | эмбеддинги `ai-forever/ru-en-RoSBERTa` (Сбер, локально) + pgvector | «не включается комп после сборки» находит сборку ПК |

- **Индекс полезности.** Байесовское среднее трёх величин: оценки, доли дошедших до конца и голосов «полезно».
- **Аналитика узких мест для автора.**
  - Воронка по шагам: сколько дошли и сколько бросили на каждом шаге.
  - Медианное время на шаге в сравнении с заявленным.
  - Голоса «полезно / не полезно» и нажатия «Застрял».
  - Индекс проблемности каждого шага с объяснением причин.
  - Сравнение версий «до / после правки» и динамика за 30 дней.
- **ИИ-инструменты** на GigaChat-2-Max (Сбер):
  - черновик инструкции по теме;
  - импорт из текста — поста с форума или конспекта;
  - улучшение отдельного шага с показом изменений;
  - проверка полноты всей инструкции;
  - **разбор узких мест**: ИИ читает метрики и комментарии учеников и предлагает новую редакцию шага, которую можно применить в черновик;
  - подсказка ученику по кнопке «Застрял».
- **Мобильная версия и офлайн-режим.**
  - Приложение устанавливается как PWA.
  - Прохождение работает без сети, события копятся в очереди.
  - Когда сеть возвращается, очередь отправляется на сервер; повторная отправка не создаёт дублей.
- **Экспорт в PDF.** Печатная версия с квадратиками чек-листов и QR-кодом на онлайн-версию.
- **Встраивание на сторонние сайты.** Виджет `/embed/<slug>` вставляется через iframe, прогресс хранится у ученика в браузере.
- **Тёмная и светлая темы.**

## Индекс узкого места

Для каждого шага считается число от 0 до 100:

| Вес | Сигнал |
|---|---|
| 50% | доля бросивших этот шаг среди дошедших до него |
| 20% | во сколько раз медианное время превышает заявленное |
| 15% | доля голосов «не полезно» |
| 15% | частота нажатий «Застрял» |

Значение ≥ 45 означает «критично», ≥ 25 — «внимание». Прохождение считается брошенным,
если в нём нет активности дольше 30 минут. Формула лежит в
[backend/app/services/analytics.py](backend/app/services/analytics.py).

## Быстрый старт

Нужны Docker, Node 22+ с pnpm, Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
make setup     # зависимости → docker compose (Postgres :5434, S3 :9010) → миграции → демо-данные
make dev       # http://localhost:3000 — сайт, http://localhost:8000/api/docs — Swagger
```

Развёртывание на сервере в Docker — в [DEPLOY.md](DEPLOY.md).

Для ИИ укажите ключ авторизации GigaChat API в `backend/.env`: `GIGACHAT_AUTH_KEY=...` (шаблон — `backend/.env.example`).
Эмбеддинги считаются локально моделью `ai-forever/ru-en-RoSBERTa`, при первом запуске она скачивается (~1.5 ГБ).
Без ключа платформа работает полностью, кроме ИИ-функций. Чтобы включить заглушку ИИ для разработки, задайте `AI_FAKE=true`.

**Демо-аккаунты** (пароль у всех `demo1234`; на странице входа есть кнопки быстрого входа):

| Email | Роль | Что показать |
|---|---|---|
| `demo@nit.demo` | автор | 4 инструкции, аналитика, входящие правки |
| `igor.vlasov@nit.demo` | эксперт | очередь проверки |
| `admin@nit.demo` | админ | роли, заявки в эксперты, расход ИИ |

**Сценарий демо, 3 минуты:**
1. На главной найдите «не включается комп после сборки» — так видно семантический поиск.
2. Откройте инструкцию «Установить Docker», пройдите пару шагов, нажмите «Застрял».
3. Войдите как `demo@nit.demo` → Студия → Docker → Аналитика. Видны узкое место «BIOS» и рост доли дошедших до конца в v2 по сравнению с v1 (+24 п.п.).
4. Нажмите «Разобрать с ИИ», затем «В черновик» и опубликуйте новую версию.
5. Откройте Студию → Правки и влейте правку эксперта.

**Офлайн-режим** работает в продакшен-сборке: `make build`, затем `PORT=3000 node frontend/.output/server/index.mjs`.
На странице инструкции нажмите «Скачать офлайн».

## Архитектура

```
Nuxt 4 (SSR + PWA) ──/api/**──► Nitro proxy ──► FastAPI ──► PostgreSQL 17 (pgvector, pg_trgm)
                   └─/media/**─► Nitro proxy ──► S3 (SeaweedFS локально; MinIO/Yandex Object Storage в проде)
                                                 FastAPI ──► GigaChat API (GigaChat-2-Max)
                                                 FastAPI ──► ru-en-RoSBERTa локально (эмбеддинги)
```

**Бэкенд** — FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2, pytest; в [backend/app/](backend/app/):
- `models.py` — модель данных:
  - `Guide`: карточка инструкции и счётчики;
  - `GuideVersion`: неизменяемые опубликованные версии и одна черновая;
  - `Step`: шаг с ключом, стабильным между версиями и форками;
  - `Run` и `StepEvent`: прохождения и события для аналитики;
  - `Comment`, `StepVote`, `Rating`, `Suggestion`, `Review`, `AiCall`.
- `services/` — логика: версии и форки, гибридный поиск, аналитика, ИИ, S3.
- `api/routes/` — роуты, по файлу на домен.
- `seed/` — демо-контент: 17 реалистичных инструкций и генератор примерно 2300 прохождений по заданным узким местам.

**Фронтенд** — Nuxt 4, Tailwind v4, shadcn-vue, Pinia, TipTap 3, `@vite-pwa/nuxt`. TS-типы генерируются из OpenAPI бэкенда командой `make types`.
